## 1. 项目概述

### 1.1 背景

学生在校期间的学业、科研、实践、就业数据分散在教务、科研、学工、实践平台、就业等多个系统中。这些系统按部门纵向建设，数据标准与统计口径不一致，集中表现为四类问题：

1. **一人多号、一数多源**——学号、考生号、身份证号并存，成绩与实践记录难以关联到同一个人；
2. **口径分散、难以复用**——综合成绩、学分完成率固化在报表模板或代码中，改口径就要改程序；
3. **画像缺失、指导粗放**——掌握大量过程数据，却缺少面向个体的能力画像，就业指导靠经验；
4. **服务缺失、重复建设**——数据以报表输出，新应用重复对接，且缺少统一的授权与审计。

### 1.2 建设目标

| 编号 | 目标 | 可度量标准 |
|---|---|---|
| G1 | 数据统一 | 接入 3 类数据源，主数据覆盖 ≥ 98% 在校生，实现「一人一档」 |
| G2 | 口径可配 | ≥ 12 项核心指标以配置管理，口径变更无需改代码 |
| G3 | 画像可解释 | 「指标—标签—画像」三层结构，每个标签可回溯口径与来源 |
| G4 | 服务可开放 | ≥ 6 个数据服务 API，支持授权、限流与版本管理 |
| G5 | 权限可管控 | 角色 + 数据范围双重校验，敏感字段全脱敏，关键操作留痕 |
| G6 | 过程可追溯 | 4 个 Sprint 均交付可运行增量，提交记录与迭代计划一一对应 |

### 1.3 范围与边界

**本期做**：三类数据源接入与稽核、清洗与主数据归并、指标口径配置、画像计算与呈现、班级看板与预警闭环、岗位推荐与解释、数据服务发布与授权、脱敏与审计。

**本期不做**：与真实教务/科研系统的生产级对接、移动端原生 App、机器学习推荐与学业预测模型、校级数据仓库等基础设施。

### 2.3 四个 Sprint

| 迭代 | 周期 | 主题 | 规模 | 演示场景 |
|---|---|---|---|---|
| Sprint 1 | 第 1—2 周 | 打通数据链路，建立最小闭环 | 8 个 / 29 点 | 导入成绩 → 合并主数据 → 学生看到自己的综合成绩 |
| Sprint 2 | 第 3—4 周 | 从数据到画像，从画像到洞察 | 9 个 / 40 点 | 辅导员在看板发现 3 名预警学生，完成认领、谈话记录与状态更新 |
| Sprint 3 | 第 5—6 周 | 从内部系统到数据服务 | 8 个 / 36 点 | 学生看推荐与理由；第三方凭令牌调用画像 API 并返回脱敏数据 |
| Sprint 4 | 第 7—8 周 | 补齐数据源，完善安全与质量 | 9 个 / 30 点 | 三源接入 → 画像 → 推荐 → 服务调用，展示审计与脱敏 |

Sprint 1 刻意只做最窄的一条链路，目的是尽早暴露数据质量问题；如果一开始就做画像界面，很容易「界面漂亮但没有可信数据」。

## 3. 系统用例分析

### 3.1 角色

| 编号 | 角色 | 所属部门 | 职责概要 |
|---|---|---|---|
| AC-01 | 学生 | 各学院 | 查看个人档案、成绩与能力画像，获取推荐并反馈 |
| AC-02 | 辅导员（班导师） | 学院学生工作办公室 | 查看班级看板，接收并处置学业预警，跟踪帮扶 |
| AC-03 | 院系管理员 | 学院教学办公室 | 查看群体分析与趋势，申请并管理部门数据服务授权 |
| AC-04 | 就业指导中心 | 学校就业指导中心 | 维护岗位与能力库、配置推荐策略、分析就业去向 |
| AC-05 | 数据管理员 | 信息化建设与管理中心 | 数据接入、治理、口径与标签维护、服务发布 |
| AC-06 | 系统管理员 | 信息化建设与管理中心 | 用户角色权限、脱敏策略、审计与系统运行 |
| AC-07 | 外部业务系统 | 教务、科研、实践平台 | 按接口规范推送增量数据 |
| AC-08 | 第三方应用 | 校园门户、就业平台 | 凭令牌调用数据服务 API |

数据管理员与系统管理员的职责必须分离：前者对数据内容负责，后者对访问控制负责，避免「既定义口径又审计自己」。

### 3.3 关键用例规约

| 用例 | 关键分支（备选流） | 业务规则 |
|---|---|---|
| UC-DC-03 执行导入任务 | 配置不完整→待配置；解析失败→允许重跑；部分校验失败→部分成功并可只重试失败记录 | 重复执行不产生重复记录；重试不影响已成功记录 |
| UC-SP-02 计算画像指标 | 口径失效→失败不生成快照；个别学生失败→重试一次后计入异常；超时→保留已完成支持断点续算 | 同周期同版本重算覆盖而非叠加；快照生成后不得静默修改 |
| UC-AA-05 处置预警 | 越权不可认领；需持续跟踪→设置提醒；学生转专业/休学→标记不适用 | 未填干预措施不得关闭；关闭后不可删历史 |
| UC-DS-04 调用数据服务 | 令牌无效→401；超配额→429；越权→403 且记录越权尝试 | 不得返回未脱敏字段；并发配额计数必须准确 |

## 4. 数据建模

### 4.1 名词短语法

从业务描述与用例描述中抽取 28 个名词短语，逐条判定：能独立存在、有生命周期、被多个用例共享的才提升为类；依附于某类、只作取值的降为属性；抽象领域名称不建类。

典型判定：**学生、数据源、导入任务、指标口径、画像快照、预警记录、岗位、数据服务** → 实体类；**成长、职业发展、质量** → 非类（落到具体类）；**综合成绩、学期、匹配度、权限范围** → 属性。

### 4.2 CRC 分析

| 类名 | 职责 | 协作者 |
|---|---|---|
| 学生 | 维护唯一身份与组织归属；作为画像、预警、推荐的主体引用 | 专业、班级、指标值、画像快照、预警记录、推荐记录 |
| 指标口径 | 定义公式、权重、周期与版本；控制口径变更的影响范围 | 指标值、标签、画像快照、数据管理员 |
| 画像快照 | 聚合某周期的指标值与标签，形成可查询、可对比的画像结果 | 学生、指标值、标签、画像报告 |
| 预警记录 | 记录触发条件、等级与处置状态；驱动干预流程 | 预警规则、学生、干预记录、辅导员 |
| 岗位 | 维护岗位信息与能力要求；为推荐提供岗位侧输入 | 能力项、岗位能力要求、推荐记录 |
| 数据服务 | 描述对外 API 的数据范围、版本与限流 | 授权申请、调用日志、第三方应用 |

「学生只负责身份与组织归属、不承担计算职责；指标口径只管『怎么算』；画像快照只负责『算完存什么』」——这种数据与规则分离的划分，正是 G2「口径可配」在模型层面的落地。

## 6. 团队分工

**分工原则**：不按「前端/后端/文档」横向切，而是「模块 owner + 横向责任」两条线——代码按模块归属到人，文档与质量责任按阶段落到不同人。

| 成员 | 主责模块（故事点） | 横向角色 |
|---|---|---|
| A（组长） | M6 数据服务与权限（31 → 实际 23） | 架构与技术选型、Git 与看板、集成联调、答辩主讲 |

## 7. 目录结构与复现

```text
实验一/
├─ README.md                     ← 本文件
├─ docs/
│  ├─ 需求规格说明书.docx          ← 正稿（41 页，18 表 16 图）
│  └─ 需求规格说明书.pdf           ← 预览版（LibreOffice 转换，以 docx 为准）
├─ diagrams/
│  ├─ png/                       ← 16 张成图
│  └─ src/                       ← 活动图、域模型的 PlantUML 源文件
└─ tools/
   ├─ reqdata.py                 ← 需求基线（单一数据源）
   ├─ build_usecase.py           ← 6 张用例图的布局配置
   ├─ render_usecase.py          ← 用例图确定性布局渲染器
   ├─ storymap.py                ← 用户故事地图渲染器
   ├─ gen_puml.py                ← 生成活动图 / 域模型的 .puml
   └─ build_docx.py              ← 生成 Word 文档
```

所有图表由代码生成，且与表格**同源**：故事、用例、角色、迭代都写在 `tools/reqdata.py` 里，改一处，地图、表格、文档一起更新，不会出现「图改了表没改」。

```powershell
$py = "C:\Users\brigh\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"
cd 实验一\tools

& $py storymap.py        # 用户故事地图
& $py build_usecase.py   # 用例图
& $py gen_puml.py        # 生成 .puml
& java -jar ..\..\.tools\plantuml.jar -charset UTF-8 -tpng -o ..\diagrams\png ..\diagrams\src\*.puml
& $py build_docx.py      # 生成 docx
```

生成后用 Word 打开，右键目录 →「更新域」刷新页码。
