# 换机部署说明

本文用于把项目从一台电脑搬到另一台电脑（或从零搭一套开发环境）。核心结论：

- **数据库不用手工建库建表**：首次连接会自动 `CREATE DATABASE`，各模块启动时自动 `CREATE TABLE IF NOT EXISTS`，角色/权限/管理员/种子规则也会自动写入。
- **需要手工准备的是环境**：MySQL 实例、账号权限、环境变量、编译器/CMake/Python，以及重新 configure 构建目录。
- **数据不会跟着代码走**：现有演示数据在本机 MySQL 数据目录里，需要 `mysqldump` 导出后在新机器导入（或重新跑演示脚本）。

---

## 1. 前置条件

| 组件 | 要求 | 说明 |
| --- | --- | --- |
| MySQL | 8.x（本项目按 8.4 开发） | **默认端口 3307**（不是 3306）；也可以改环境变量 |
| C++ 编译器 | 支持 C++17 | MinGW-w64 GCC 13+ 或 Visual Studio 的“使用 C++ 的桌面开发” |
| CMake | ≥ 3.21 | |
| Ninja | 可选 | MinGW/命令行构建推荐；VS 生成器不需要 |
| Python | 3.8+ | 跑 `http_smoke`、`seed_demo.py`；没有 Python 时 CMake 会跳过 HTTP 测试 |
| MySQL 客户端库 | 头文件 + 库（libmysql） | Windows 用官方 ZIP 自带的 `include/mysql.h`、`lib/libmysql.lib` |

> 换机时**不要拷贝** `build/` 目录：里面的 CMakeCache 记录的是旧机器的绝对路径，必须重新 configure。
> `.vscode/` 里的 `launch.json`/`settings.json` 如果写死了旧机器路径，也要按新机器改。

## 2. 数据库准备

### 2.1 方式 A：本地 MySQL（和当前开发机一致）

Windows 便携版示例（路径按实际解压位置调整）：

```powershell
$base = "$env:LOCALAPPDATA\Programs\mysql-8.4.13\mysql-8.4.13-winx64"
$data = "$env:LOCALAPPDATA\mysql-data-8.4"

# 首次使用（数据目录为空时）先初始化，root 空密码，仅本机开发用
if (-not (Test-Path "$data\mysql")) {
  & "$base\bin\mysqld.exe" --initialize-insecure --basedir="$base" --datadir="$data"
}

& "$base\bin\mysqld.exe" --basedir="$base" --datadir="$data" `
  --port=3307 --bind-address=127.0.0.1 --mysqlx=0 --console
```

检查是否启动：

```powershell
& "$base\bin\mysqladmin.exe" --protocol=tcp --host=127.0.0.1 --port=3307 --user=root ping
```

### 2.2 方式 B：Docker（最省事，端口固定）

```yaml
# docker-compose.yml（放到项目里或任意目录）
services:
  mysql:
    image: mysql:8.4
    container_name: platform-mysql
    ports:
      - "3307:3306"
    environment:
      MYSQL_ROOT_PASSWORD: root
      TZ: Asia/Shanghai
    command: --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
    volumes:
      - platform-mysql-data:/var/lib/mysql
volumes:
  platform-mysql-data:
```

```bash
docker compose up -d
```

### 2.3 建账号与授权（两种方式都要做）

用 root 登录（本地空密码 / Docker 里是 `root`），执行：

```sql
CREATE USER IF NOT EXISTS 'platform'@'%' IDENTIFIED BY 'PlatformPass123!';
GRANT ALL PRIVILEGES ON *.* TO 'platform'@'%';
FLUSH PRIVILEGES;
```

> 为什么给 `ALL PRIVILEGES`：项目会**自动创建主库和测试库**，需要 `CREATE DATABASE` 权限。
> 生产环境请改成“预先建库 + 只授权目标库”，并换成强密码。

### 2.4 不需要执行的 SQL

以下都是代码自动完成的，新机器**不用手工执行**：

- `CREATE DATABASE student_platform`（首次连接自动建，`utf8mb4`）
- 各模块建表：`ing_*`、`gov_*`、`sp_*`、`aa_*`、`cd_*`、`users/roles/...`
- 种子数据：角色与权限、M2 质量规则/指标口径/演示学生、M4 默认规则 R1–R4
- 管理员账号（需要设置 `PLATFORM_ADMIN_PASSWORD`，见下一节）

## 3. 环境变量

项目没有 `.env` 文件，全部通过环境变量配置。

| 变量 | 默认值 | 必需 | 用途 |
| --- | --- | --- | --- |
| `PLATFORM_ADMIN_PASSWORD` | 无 | **首次启动必需** | 首次启动创建 `admin` 账号，至少 12 位；不设且库为空时服务会报错退出 |
| `PLATFORM_DB_URL` | 无 | 否 | 完整连接串，优先生效：`mysql://user:password@host:port/database` |
| `PLATFORM_DB_HOST` | `127.0.0.1` | 否 | 主机 |
| `PLATFORM_DB_PORT` | `3307` | 否 | 端口 |
| `PLATFORM_DB_USER` | `platform` | 否 | 账号 |
| `PLATFORM_DB_PASSWORD` | `PlatformPass123!` | 否 | 密码 |
| `PLATFORM_DB_NAME` | `student_platform` | 否 | 主库名 |
| `PLATFORM_TEST_DB` | `0` | 测试时 | 设为 `1` 时每个测试进程用独立库 `..._test_<pid>_<timestamp>` |
| `PLATFORM_CAREER_DEMO` | `0` | 否 | 设为 `1` 时 M5 职业推荐使用独立演示库 `student_platform_career_demo`，M6 仍用主库 |
| `MYSQL_ROOT` | 无 | 否 | CMake 找 MySQL ZIP 根目录用（等价于 `-DPLATFORM_MYSQL_ROOT=`） |

PowerShell 示例：

```powershell
$env:PLATFORM_ADMIN_PASSWORD = "AdminPassword123!"   # 至少 12 位
$env:PLATFORM_CAREER_DEMO    = "1"                   # 可选：M5 演示模式
# 数据库不在默认地址时再加：
# $env:PLATFORM_DB_URL = "mysql://platform:PlatformPass123!@127.0.0.1:3307/student_platform"
```

> `seed_demo.py` 登录时读取的也是 `PLATFORM_ADMIN_PASSWORD`，不设则默认 `AdminPassword123!`。

## 4. 构建

### 4.1 Windows + Visual Studio（推荐给有 VS 的机器）

```powershell
cmake --preset windows-vs2026
cmake --build --preset windows-vs2026
```

前提：安装 Visual Studio 的 **“使用 C++ 的桌面开发”** 和 **“C++ CMake tools for Windows”**。preset 生成器是 `Visual Studio 18 2026`，输出到 `build/windows-vs2026`。

> 如果新机器装的是 VS 2022/2019，这个 preset 会报生成器不存在：把 `CMakePresets.json` 里 `windows-vs2026` 的 `generator` 改成 `"Visual Studio 17 2022"`（或对应版本），或者直接用 4.2 的 MinGW 方式。

### 4.2 Windows + MinGW + Ninja（当前开发机用的方式）

```powershell
cmake -S . -B build/develop-check -G Ninja `
  -DCMAKE_BUILD_TYPE=Debug `
  -DCMAKE_CXX_COMPILER="C:/w64devkit/w64devkit/bin/g++.exe" `
  -DPLATFORM_MYSQL_ROOT="C:/Users/<你>/AppData/Local/Programs/mysql-8.4.13/mysql-8.4.13-winx64" `
  -DPython3_EXECUTABLE="C:/Users/<你>/AppData/Local/Programs/Python/Python314/python.exe"

cmake --build build/develop-check
```

说明：

- `PLATFORM_MYSQL_ROOT` 不传时，Windows 会自动尝试 `%LOCALAPPDATA%\Programs\mysql-8.4.13\mysql-8.4.13-winx64`。
- 不指定 `Python3_EXECUTABLE` 时 CMake 会自己找；找不到就不会注册 `http_smoke`。
- MinGW 构建会静态链接运行库，并把 `libmysql.dll`、`libssl-3-x64.dll`、`libcrypto-3-x64.dll` 复制到 exe 目录，换机后不需要额外装 MySQL 客户端 DLL。
- `-DCMAKE_BUILD_TYPE=Debug` 便于调试；发布可换 `Release`。

### 4.3 Linux

```bash
sudo apt-get install -y cmake g++ python3 libmysqlclient-dev mysql-client
cmake --preset linux-debug
cmake --build --preset linux-debug
```

## 5. 首次启动与验证

1. 确认 MySQL 在 3307 可用（`mysqladmin ping`）。
2. 设置管理员密码并启动（演示模式加 `PLATFORM_CAREER_DEMO=1`）：

```powershell
$env:PLATFORM_ADMIN_PASSWORD = "AdminPassword123!"
$env:PLATFORM_CAREER_DEMO    = "1"
.\build\develop-check\platform_server.exe 8090
```

3. 另开终端验证：

```powershell
curl.exe http://127.0.0.1:8090/api/health
# 期望：{"status":"ok"}

$login = Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:8090/api/modules/data-services/login `
  -ContentType 'application/json' `
  -Body '{"username":"admin","password":"AdminPassword123!"}'
$login.access_token
```

4. 浏览器打开 <http://127.0.0.1:8090/workspace>，用 `admin / AdminPassword123!` 登录。

> 端口可以自选（`platform_server.exe 8080`），但 `seed_demo.py` 和前端联调默认用你启动时传的端口。

## 6. 演示数据

```powershell
py -3 scripts/seed_demo.py 8090
```

当前脚本覆盖 **M1 数据接入 + M3 学生画像**（数据源、映射、导入、学生、指标、标签、批量重算）。M2/M4 需要再手动触发一次：

```powershell
$h = @{ Authorization = "Bearer " + $login.access_token }

# M2：按学期重算指标（会写 sp_metric_value 并同步 sp_student）
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8090/api/modules/data-governance/recalculate" `
  -Headers $h -ContentType 'application/json' -Body '{"term":"2025-2026-1"}'

# M4：按规则生成预警
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8090/api/modules/academic-alerts/alerts/generate" `
  -Headers $h
```

注意：M4 的指标来自 `sp_metric_value`，且按最新学期取值。如果 M2 重算时没传 `term`，指标学期是空字符串，导出的预警里 `metric_term` 也会是空。

完整的一键端到端校验（M1→M6，19 个步骤）：

```powershell
py -3 scripts/e2e_demo.py 8090
```

失败时会打印失败的步骤、请求方法与路径、HTTP 状态和响应体。M5 需要服务端以 `PLATFORM_CAREER_DEMO=1` 启动，否则加 `--skip-career`。

## 7. 测试

```powershell
$env:PLATFORM_TEST_DB = "1"
ctest --test-dir build/develop-check --output-on-failure
```

- 期望 **11/11 通过**。
- 测试库名格式 `student_platform_test_<pid>_<timestamp>`，同一测试进程内所有模块共用一个库。
- 测试账号需要 `CREATE DATABASE` 权限；`http_smoke` 还需要 PATH 里有 `mysql.exe`（或 CMake 通过 `PLATFORM_MYSQL_ROOT/bin/mysql.exe` 自动设置 `MYSQL_CLIENT`）。
- 测试库会累积，可以定期清理：

```sql
-- 列出残留库，并生成删除语句
SELECT CONCAT('DROP DATABASE `', schema_name, '`;')
FROM information_schema.schemata
WHERE schema_name LIKE 'student_platform\_test\_%';
```

## 8. 迁移现有数据（可选）

换机后如果不想从头造演示数据，把旧机器的两个库导出来：

```powershell
# 旧机器（建议先停掉 8090 服务）
mysqldump -h127.0.0.1 -P3307 -uplatform -pPlatformPass123! `
  --default-character-set=utf8mb4 --databases student_platform student_platform_career_demo `
  > platform-dump.sql
```

```powershell
# 新机器（MySQL 已启动）
mysql -h127.0.0.1 -P3307 -uplatform -pPlatformPass123! --default-character-set=utf8mb4 < platform-dump.sql
```

注意事项：

- 如果旧机器没开过 M5 演示模式，`student_platform_career_demo` 可能不存在，导出参数里去掉它即可。
- 迁移后管理员密码沿用旧库里的哈希；想换密码就在新库清空 `users` 表后重启并设置新的 `PLATFORM_ADMIN_PASSWORD`（仅演示环境这么做）。
- 只迁移代码不迁移数据时，新库第一次启动会自动建表、建管理员（需要 `PLATFORM_ADMIN_PASSWORD`）。

## 10. 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| `cannot connect to MySQL: Can't connect ... (10061)` | MySQL 没启动，或端口不是 3307/没监听 127.0.0.1；用 `mysqladmin ping` 确认，或设置 `PLATFORM_DB_PORT` |
| `Access denied for user 'platform'` (1045) | 账号/密码不对；库名和主机也要注意 `'platform'@'%'` 与 `'platform'@'localhost'` 是不同账号 |
| `cannot create database ...` (1044) | 账号没有 `CREATE DATABASE` 权限（测试库也依赖它） |
| 启动报 `first start requires PLATFORM_ADMIN_PASSWORD (at least 12 characters)` | 非演示模式 + 空库 + 没设密码；设置该变量后重启 |
| 改了密码但登录失败 | 管理员只在库为空时创建；已有用户不会自动改密码 |
| `MySQL headers not found` | 重新 configure 并指定 `-DPLATFORM_MYSQL_ROOT=<MySQL ZIP 根目录>` |
| 链接 `platform_server.exe` 失败 / 拒绝访问 | Windows 上 exe 正被 8090 进程占用；先停服务再构建 |
| 测试连到了主库 | 忘了 `$env:PLATFORM_TEST_DB = "1"` |
| `http_smoke` 不在测试列表 | CMake 没找到 Python；加 `-DPython3_EXECUTABLE=...` 重新 configure |
| 中文乱码 | 确认库/连接是 `utf8mb4`（代码默认）；Windows 控制台可先 `chcp 65001` |
