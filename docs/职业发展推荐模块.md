### 职业发展推荐模块

#### 本地运行

从仓库根目录执行以下命令

```sh
cmake --preset linux-debug
cmake --build --preset linux-debug
ctest --preset linux-debug
PLATFORM_CAREER_DEMO=1 ./build/platform_server 8080
```

- 第一条命令在 Linux 和 macOS 使用预设配置 Debug 构建，在 `build/` 生成 Makefile 和 `compile_commands.json`
- 第二条按同一预设编译平台服务和测试，第三条运行应用、共享存储和实际 HTTP 测试
- 第四条在本次服务进程启用职业推荐本地演示模式，监听本机 `8080` 端口

Windows 使用仓库现有的 `windows-vs2026` 构建预设，在 PowerShell 中先设置 `$env:PLATFORM_CAREER_DEMO = '1'`，使随后启动的服务继承演示开关，再用 `.\build\windows-vs2026\Debug\platform_server.exe 8080` 启动 Debug 服务

打开 [平台首页](http://127.0.0.1:8080/)，点「职业发展推荐 · 岗位管理与学生推荐」。新增一条岗位，填写行业、岗位类型、说明和能力要求，保存草稿后发布。策略默认显示 60／40，点击「保存并生效」才写入数据库

演示请求使用 `X-Career-Demo: 1`，并由仅监听回环地址的平台服务处理。数据库是服务工作目录下的 `data/career-demo.db`，与平台数据库分开

正式模式使用 `/career` 页面中的统一登录或 [M6 登录接口](data-services.md)。使用 `career_center` 账号管理岗位与策略，使用绑定学号的学生账号查询本人推荐。未认证返回 `401`，无权限或全校范围不足返回 `403`。正式岗位和策略写入与统一审计同事务提交

演示模式点击「学生视图」可切换两份独立样例画像。用下方岗位示例，将两项达标线都设为 80，并保存 60／40 的策略。学生 A 有编程 80 分和数据库 40 分，预计得到 80.00 分；学生 B 只有编程 80 分，预计得到 75.00 分。点「查看匹配理由与反馈」，可看到逐项贡献和缺失状态，并保存意向及原因

在「就业指导中心」视图点「查询统计」，可查看去向分布、就业行业分布和历年趋势。演示样例覆盖 2023 至 2025 届，年份留空时显示全部 8 人，筛选 2024 年时显示 3 人、其中 2 人已就业。正式模式的去向数据与权限配置见文末联调说明

#### 接口

统一前缀为 `/api/modules/career-recommendation`，写入请求和响应使用 JSON

| 用例 | 请求 | 成功响应 |
| --- | --- | --- |
| UC-CD-01 | `GET /jobs` | `200`，返回所有状态的岗位数组，按 ID 降序 |
| UC-CD-01 | `POST /jobs` | `201`，返回新建的草稿岗位 |
| UC-CD-01、07 | `PUT /jobs/:id` | `200`，返回更新后的岗位和能力要求 |
| UC-CD-07 | `PUT /jobs/:id/status` | `200`，返回状态更新后的岗位 |
| UC-CD-02 | `GET /strategy` | `200`，返回当前生效策略 |
| UC-CD-02 | `PUT /strategy` | `200`，返回保存后生效的策略 |
| UC-CD-03 | `POST /recommendations/query` | `200`，返回按分数排序的本人推荐列表 |
| UC-CD-04 | `GET /recommendations/:id/reason` | `200`，返回保存时的岗位和能力匹配快照 |
| UC-CD-05 | `PUT /recommendations/:id/feedback` | `200`，返回更新后的本人反馈 |
| UC-CD-06 | `GET /outcomes` | `200`，返回指定毕业年份范围内的去向分布、就业行业分布和历年趋势 |

**岗位请求示例**

```json
{
  "title": "C++ 开发实习生",
  "industry": "信息技术",
  "job_type": "internship",
  "description": "参与 C++ 服务开发与测试",
  "requirements": [
    {"competency_code": "programming", "threshold": 80, "weight": 3},
    {"competency_code": "databases", "threshold": 75, "weight": 1}
  ]
}
```

- `job_type` 为校招 `campus` 或实习 `internship`。岗位包含 1 到 100 条能力要求，同一岗位的能力标识唯一，达标分和权重均大于 0 且不超过 100。能力标识示例供演示使用，正式映射按学生画像模块约定
- 返回值附带正整数 `id`、`version` 和 `status`。普通编辑保留发布状态。状态接口提交 `{"status":"published"}` 或 `{"status":"withdrawn"}`，支持草稿 → 已发布 → 已下架 → 已发布
- 岗位内容或状态确实变化时版本递增。岗位与能力要求作为一条 SQLite 记录原子更新

**策略请求示例**

```json
{
  "algorithm": "pass_and_proximity",
  "min_score": 50,
  "pass_weight": 60,
  "proximity_weight": 40,
  "allowed_industries": ["信息技术"],
  "allowed_job_types": ["internship"]
}
```

- `weighted_pass` 使用 100／0，`pass_and_proximity` 的两项权重各为 0 到 100，且至少一项大于 0。最低推荐分为 0 到 100。两个筛选列表各自为空时表示不限
- 策略表只有一条生效记录，成功保存后返回 `version`。重复保存等价配置保留版本。推荐查询读取当前生效配置
- 格式或字段无效返回 `400`，岗位不存在返回 `404`，未配置策略或草稿直接下架返回 `409`。错误响应体包含 `error` 字段
