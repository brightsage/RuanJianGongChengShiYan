## 3. 数据库架构（本轮已迁移）

- `include/platform/db.hpp` / `src/platform/db.cpp`：MySQL 薄封装。
  - 连接串：`mysql://user:password@host:port/database`
  - 环境变量：`PLATFORM_DB_URL`，或 `PLATFORM_DB_HOST/PORT/USER/PASSWORD/NAME`
  - `PLATFORM_TEST_DB=1`：测试库名追加 `_test_<pid>_<timestamp>`
  - 参数绑定是**客户端转义后拼接 SQL**，不是 MYSQL_STMT；所有模块 SQL 都走这一层。
  - 支持多语句 `exec`、查询、事务、`last_insert_rowid`。
- 不再有 SQLite；`third_party/sqlite` 已删除。
- 旧 SQLite 数据没有迁移；MySQL 是全新 schema。
- MySQL DDL 会隐式提交：**建表必须放在事务外**。M5 曾经在请求事务里建表，导致审计失败无法回滚，已修复为模块启动时建表。后续 M2/M4 也要遵守。

当前主要表：

- M1：`ing_data_source`、`ing_field_mapping`、`ing_import_task`、`ing_import_run`、`ing_raw_record`
- M2：`gov_quality_rule`、`gov_student_master`、`gov_metric_def`、`gov_recalc_task`
- M3：`sp_student`（含 `org_id`）、`sp_metric_value`、`sp_tag`、`sp_student_tag`、`sp_profile_snapshot`
- M4：`aa_alert_rule`、`aa_alert_record`、`aa_intervention`
- M5：`cd_jobs`、`cd_strategy`、`cd_recommendations`、`cd_feedback`
- M6：`users`、`roles`、`permissions`、`sessions`、`services`、`applications`、`grants`、`audit_logs`、`call_logs`、`masking_rules`、`settings`

## 4. 已完成的关键行为

### M1 数据采集与接入

- 14 条路由：数据源、字段映射、任务、执行、结果、失败重试、外部推送。
- 支持 `idempotency_key`、失败记录重试、字段转换、导入校验。
- 所有路由要求 `ingestion.read` / `ingestion.write`，且要求全校范围；学生/辅导员访问返回 403。

### M3 学生画像

- 12 条路由：学生同步、指标、画像、证据、对比、报告、按学期批量重算。
- `sp_student.org_id` 用于 M6 数据范围。
- 权限：
  - `profile.read`：学生本人、辅导员本班、院系本学院、数据/系统管理员全校。
  - `profile.write`：同步学生/指标、标签、重算；批量重算只允许全校范围。
- M5 职业推荐直接读取 `sp_metric_value` / `sp_profile_snapshot`，这条链路是通的。

### M2 数据治理

- 6 条路由：质量规则（`GET/POST /quality-rules`）、学生主数据（`GET /student-master/:id`、`POST /student-master/merge`）、指标重算（`POST /recalculate`）、质量报告（`GET /quality-report`）。
- 四张 `gov_` 表在模块启动时建表；种子规则、演示学生、指标口径用 `INSERT IGNORE` 写入，不覆盖已有配置。
- 主数据归并只覆盖非空字段；归并后同步写 `sp_student`。
- `/recalculate` 读取 `ing_raw_record`（按 `student_id`/`student_no`/`学号` 关联，按记录 ID 去重），并只读 `ing_field_mapping` 把 `xh`/`cj` 这类源字段还原成标准字段；按 `gov_metric_def.formula`（`avg/sum/count/max/min/pass_rate`）计算，写 `sp_metric_value`（`source=governance`），并落一条 `gov_recalc_task`。
- 质量报告是实时统计：原始记录数、脏数据数、质量得分、主数据覆盖率。
- 权限：`governance.read/write`，只给 `system_admin`、`data_admin`，要求全校范围。

### M4 学业预警

- 9 条路由：看板、规则、生成、预警列表、认领、处置、干预记录、学业趋势。
- 三张 `aa_` 表在模块启动时建表；默认规则 R1～R4 用 `INSERT IGNORE` 写入。
- 学生与指标只读 M3 的 `sp_student` / `sp_metric_value`（指标由 M2 计算），指标码通过 `metric_bindings()` 映射；没有指标值的学生不参与判定。
- 生成幂等：同一学生同一规则存在 `open/claimed` 预警时跳过；预警与干预记录都落库，重建 App 后仍在。
- 权限：`alert.read/write`；辅导员本班、院系本学院、数据/系统管理员全校；配置规则需要全校范围。

### M6 数据服务

- M3 向网关注册了只读提供方 `student_profile`，字段 `student_id/student_no/class_id/class_name/name/major/org_id/grade`；`parameters.student_id` 可过滤单个学生。
- 对外链路：`POST /services` 发布 → `POST /applications` 申请 → `POST /applications/:id/decision` 批准（必须换另一个账号）→ `POST /applications/:id/token` 签发 `svc_` 令牌 → `POST /services/:id/invoke` 调用 → `POST /applications/:id/revoke` 撤销。
- 申请需要 `grants.apply`（`college_admin`/`third_party`），批准需要 `grants.approve`（`data_admin`）；数据管理员没有 `grants.apply`，演示时用两个账号。
- 网关按授权范围过滤记录，并按 `masking_rules` 脱敏（姓名 partial、学号/成绩等 redact）。

### M6 权限

- 新增权限：`ingestion.read`、`ingestion.write`、`profile.read`、`profile.write`、`governance.read`、`governance.write`。
- 旧库启动时 `Store` 会给已有角色追加新权限，保留管理员自定义权限。
- M1/M2/M3 已接入；M4 尚未接入。

### 前端

- `/workspace` 是 M1–M4 统一工作台，已覆盖数据接入、数据治理、学生画像、学业预警。
- 四个业务页签都需要登录（`admin / AdminPassword123!`）；M2 支持规则启停/主数据列表/按学期重算，M4 支持筛选/分页/规则启停/认领处置。
- `/career`、`/data-services` 保持原有页面，并增加了“返回工作台”入口。
- 前端目前是开发/演示用，不是最终产品页面。
