# 数据采集与接入 / 学生画像 模块说明

本文档对应 `feature/WeiEnRui` 分支。两个模块已经从“只有数据层”推进到**可运行的 HTTP 接口**：数据源、字段映射、导入任务、导入执行、原始记录、学生读模型、指标、标签、画像快照和 HTML 报告都已接通。`tests/module_api_test.cpp` 和 `tests/http_smoke.py` 覆盖了完整业务流。

## 2. 分层结构

```
HTTP 请求
   │
   ▼
module.cpp                      只做模块注册、路由登记、参数转发
   │
   ▼
service.cpp                     参数校验、用例编排、导入校验、标签计算
   │
   ▼
repository.hpp                  持久化接口（可替换实现、方便测试）
   │
   ▼
sqlite_repository.cpp           SQL 与表结构
   │
   ▼
platform::Database              SQLite 连接、参数绑定、事务
```

约定：

- `module.cpp` 不写业务规则，只把请求转给 service。
- `service.cpp` 负责“能不能导入”“标签是否命中”“报告怎么生成”。
- `repository` 只负责读写，不判断业务。
- HTTP 请求/响应仍然使用 `platform::Request` / `platform::Response`。

## 3. 数据采集与接入模块（M1）

路由前缀：`/api/modules/data-ingestion`。

### 3.1 接口

| 用例 | 方法与路径（相对前缀） | 说明 |
| --- | --- | --- |
| UC-DC-01 登记数据源 | `POST /sources` | 名称、类型、接入方式、责任人；名称重复返回 409 |
| 查询数据源 | `GET /sources`、`GET /sources/:id` | 列表/详情 |
| UC-DC-07 维护字段映射 | `PUT /sources/:id/mappings` | 整体替换；支持 `trim`、`lower`、`upper`、`number` |
| UC-DC-02 配置导入任务 | `POST /tasks` | 数据源、导入方式、校验规则 |
| 查询导入任务 | `GET /tasks`、`GET /tasks/:id` | 列表/详情 |
| UC-DC-06 调度采集任务 | `PUT /tasks/:id/schedule` | 保存导入方式与调度表达式，暂不启动定时器 |
| UC-DC-03 执行导入任务 | `POST /tasks/:id/run` | 逐行映射、校验、写入原始记录；支持 `idempotency_key` |
| UC-DC-04 查看导入结果 | `GET /runs/:id`、`GET /runs/:id/records?failed=1` | 汇总与失败明细 |
| UC-DC-03 重试失败记录 | `POST /runs/:id/retry` | 只重跑失败行；可带修正后的 `records` 和 `idempotency_key` |
| UC-DC-05 接收外部数据推送 | `POST /push` | 按 `task_id` 或 `source_id` 执行；没有推送任务时自动创建；支持 `idempotency_key` |

导入请求示例：

```json
{
  "records": [
    {"xh": " 2023001 ", "cj": "92"},
    {"xh": "", "cj": "50"}
  ]
}
```

返回：

```json
{
  "run": {"id": 1, "task_id": 1, "status": "partial",
          "total_count": 2, "success_count": 1, "failure_count": 1},
  "failures": [
    {"source_row_no": 2, "valid": false, "error_reason": "missing required field 'student_id'"}
  ]
}
```

执行导入或外部推送时可以带 `idempotency_key`：同一个任务重复提交同一个 key 会直接返回第一次的执行结果，不会重复生成 `ing_raw_record`。失败记录用 `POST /runs/:id/retry` 重跑；不带 `records` 时重跑原始失败行，带 `records` 时用修正后的数据。

### 3.2 映射与校验规则

字段映射把源字段转成标准字段：

```json
[
  {"source_field": "xh", "standard_field": "student_id", "transform_expr": "trim"},
  {"source_field": "cj", "standard_field": "score", "transform_expr": "number"}
]
```

任务校验规则支持：

```json
{
  "required": ["student_id", "score"],
  "types": {"student_id": "string", "score": "number"},
  "ranges": {"score": {"min": 0, "max": 100}}
}
```

- `required`：字段缺失、为 null 或空字符串都算失败。
- `types`：`number` / `string` / `boolean`。
- `ranges`：只对数字字段生效，支持 `min`、`max`。

### 3.3 表结构

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `ing_data_source` | `name`、`kind`、`access_mode`、`owner` | 数据源登记，名称唯一 |
| `ing_field_mapping` | `data_source_id`、`source_field`、`standard_field`、`transform_expr` | 源字段到标准字段 |
| `ing_import_task` | `data_source_id`、`import_mode`、`schedule_expr`、`validation_rules`、`status` | 任务配置 |
| `ing_import_run` | `task_id`、`status`、`total_count`、`success_count`、`failure_count` | 每次执行结果 |
| `ing_raw_record` | `run_id`、`source_row_no`、`payload`、`valid`、`error_reason` | 原始记录与失败原因 |

约束：

- `ing_raw_record` 对 `(run_id, source_row_no)` 唯一。
- 外键开启，删除数据源会级联删除映射。
- `replace_field_mappings` 在一个事务里完成“删旧 + 写新”。

## 4. 学生画像模块（M3）

路由前缀：`/api/modules/student-profile`。

### 4.1 接口

| 用例 | 方法与路径（相对前缀） | 说明 |
| --- | --- | --- |
| 同步学生读模型 | `POST /students` | 由治理模块调用；`student_id` 已存在时更新 |
| UC-SP-07 查看学生画像详情 | `GET /students?major=&class=` | 按专业/班级过滤 |
| UC-SP-03 查看个人画像 | `GET /students/:id?term=` | 学生、指标、标签、快照 |
| 同步指标值 | `POST /metrics` | 由治理模块调用；按学生+指标+学期 upsert |
| UC-SP-01 维护标签体系 | `POST /tags`、`GET /tags` | 标签定义与规则 |
| UC-SP-02 计算画像指标 | `POST /recalculate` | 单个学生：指标 → 标签 → 快照 |
| UC-SP-02 批量计算 | `POST /recalculate/batch` | 按学期批量重算；不传 `student_ids` 时计算全部学生 |
| UC-SP-04 查看标签依据 | `GET /students/:id/tags/:code/evidence?term=` | 规则、取到的指标值、来源 |
| UC-SP-05 对比画像 | `GET /students/:id/compare?peer=&term=` | 指标差值与标签差异 |
| UC-SP-06 导出画像报告 | `GET /students/:id/report?term=` | 返回 HTML；默认页面展示，加 `download=1` 下载 |

批量计算示例：

```json
{"term": "2026-fall", "student_ids": ["2023001", "2023002"]}
```

不传 `student_ids` 时会对全部学生重算，返回每个学生的指标数、标签数和标签代码。标签结果按 `(student_id, tag_code, term)` 唯一，重算某一学期不会覆盖其它学期。

标签规则示例：

```json
{"metric": "comprehensive_score", "operator": ">=", "value": 90}
```

支持 `>=`、`>`、`<=`、`<`、`==`、`!=`、`between`。`between` 使用 `min`/`max`：

```json
{"metric": "comprehensive_score", "operator": "between", "min": 80, "max": 90}
```

画像查询返回：

```json
{
  "student": {"student_id": "2023001", "name": "张三", "major": "软件工程"},
  "term": "2026-fall",
  "metrics": [{"metric_code": "comprehensive_score", "value": 95, "unit": "分"}],
  "tags": [
    {"code": "score_excellent", "name": "成绩优秀",
     "evidence": {"metric": "comprehensive_score", "value": 95,
                  "rule": {"metric": "comprehensive_score", "operator": ">=", "value": 90}}}
  ],
  "snapshot": {"term": "2026-fall", "payload": {"metrics": {}, "tags": []}}
}
```

### 4.2 表结构

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `sp_student` | `student_id`、`name`、`major`、`class_name`、`grade` | 学生读模型，主数据由治理模块负责 |
| `sp_metric_value` | `student_id`、`metric_code`、`term`、`value`、`source` | 指标值，学生+指标+学期唯一 |
| `sp_tag` | `code`、`name`、`dimension`、`description`、`rule` | 标签定义与规则 JSON |
| `sp_student_tag` | `student_id`、`tag_code`、`term`、`evidence` | 标签结果与依据，按学期隔离 |
| `sp_profile_snapshot` | `student_id`、`term`、`payload` | 按学期保存的画像快照 |

`sp_student` 是读模型：治理模块合并出学生主数据后同步过来，画像模块不负责“一人多号”的归并。

## 5. 数据库使用方式

- 默认数据库文件：`data/platform.db`。
- 可用环境变量覆盖：

  ```powershell
  $env:PLATFORM_DB_PATH = "D:\tmp\platform.db"
  ```

- 每个模块在构造仓储时执行 `CREATE TABLE IF NOT EXISTS`，第一次启动自动建表。
- 已开启外键、WAL 和 5 秒 busy timeout。
- 表名按模块加前缀（`ing_`、`sp_`），合并后共用一个数据库文件也不会撞表。
- `sp_tag.rule`、`sp_student_tag.term`、`ing_import_run.idempotency_key` 都有兼容迁移：旧库启动时会自动补列，`sp_student_tag` 会重建表以加入新唯一约束。
- 目前没有完整的版本化迁移，新增列时在各自仓储里写兼容逻辑，不要直接删表。

## 6. 构建与运行

### 6.1 VS Code（Windows）

1. 安装并启用 CMake Tools、C/C++ 扩展。
2. 打开项目根目录，选择 preset `windows-vs2026`。
3. `F7` 构建，`F5` 运行 `platform_server`（`.vscode/launch.json` 已配置）。
4. CMake Tools 的 Testing 面板或 `ctest --preset windows-vs2026` 跑测试。

如果 Visual Studio 报找不到 `cl.exe` 或 `cmake.exe`，打开 Visual Studio Installer → 修改 → 勾选“使用 C++ 的桌面开发”和“C++ CMake tools for Windows”。

### 6.2 MinGW 备用构建

任何 MinGW-w64 GCC 13+ 都可以构建；`CMakeLists.txt` 会在 MinGW 下静态链接运行库，生成的 exe 不依赖编译器 DLL：

```powershell
cmake -S . -B build/mingw-debug -G Ninja -DCMAKE_BUILD_TYPE=Debug `
      -DCMAKE_C_COMPILER=gcc -DCMAKE_CXX_COMPILER=g++
cmake --build build/mingw-debug
ctest --test-dir build/mingw-debug --output-on-failure
.\build\mingw-debug\platform_server.exe 8090
```

如果 `ctest` 列表里没有 `http_smoke`，说明 CMake 没找到可用的 Python，可以显式指定：

```powershell
cmake -S . -B build/mingw-debug -G Ninja -DCMAKE_BUILD_TYPE=Debug `
      -DCMAKE_C_COMPILER=gcc -DCMAKE_CXX_COMPILER=g++ `
      -DPython3_EXECUTABLE="C:/Users/你的用户名/AppData/Local/Programs/Python/Python314/python.exe"
```

### 6.3 Linux

```bash
cmake --preset linux-debug
cmake --build --preset linux-debug
ctest --preset linux-debug
./build/linux-debug/platform_server 8090
```

浏览器打开 <http://127.0.0.1:8090/>。如果 8080 被其它程序占用，就用 8090。

## 7. 演示流程

启动服务后执行：

```powershell
py -3 scripts/seed_demo.py 8090
```

脚本会写入一个教务数据源、字段映射、导入任务、两名学生、指标、两个标签和画像快照，并打印画像、报告、对比地址。导入使用 `seed-run-v1` 作为幂等键，重复执行不会重复生成执行记录；画像使用批量重算接口。

也可以手动走一遍：

```powershell
$base = "http://127.0.0.1:8090/api/modules"
Invoke-RestMethod -Method Post -Uri "$base/data-ingestion/sources" `
  -ContentType "application/json" `
  -Body '{"name":"教务成绩样例","kind":"academic","access_mode":"file","owner":"教务处"}'
```

## 9. 可继续优化的点

1. **真正的调度器**：`schedule_expr` 目前只保存配置，需要后台线程/定时器执行。
2. **权限与脱敏**：接入 M6 的角色、数据范围和脱敏结果；当前画像查询没有鉴权。
3. **PDF 报告**：当前 `report` 返回 HTML；PDF 留到前端/后续迭代。
4. **主数据与指标联动**：目前 `POST /students`、`POST /metrics` 由治理模块或演示脚本同步；正式联调时应由治理模块在合并主数据/重算指标后调用。
5. **导入文件格式**：当前只接收 JSON 数组；CSV/Excel 样例文件导入可以后续补。
