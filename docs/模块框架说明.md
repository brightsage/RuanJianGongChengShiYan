# 数据采集与接入 / 学生画像 模块框架

本文档对应 `feature/WeiEnRui` 分支，说明两个模块在现有平台骨架上的分层、数据表、接口规划和后续实现顺序。当前提交只搭好基础设施和数据访问层，**没有注册业务路由**，所以 `GET /api/modules` 仍然显示两个模块“尚无业务路由”，未实现地址仍返回 404。

## 1. 已经具备的内容

| 内容 | 位置 | 作用 |
| --- | --- | --- |
| JSON 解析与输出 | `include/platform/json.hpp`、`src/platform/json.cpp` | 解析请求体、生成响应体，支持对象/数组/字符串/数字/布尔/null、转义和 `\uXXXX` |
| SQLite 封装 | `include/platform/db.hpp`、`src/platform/db.cpp` | 打开数据库、执行 SQL、参数绑定、查询、事务、读取列 |
| SQLite 3.54.1 | `third_party/sqlite/` | 官方 amalgamation，源码直接编译，不需要安装数据库服务 |
| 数据接入模型 | `src/modules/data_ingestion/model.hpp` | 数据源、字段映射、导入任务、导入执行、原始记录 |
| 数据接入仓储 | `repository.hpp`、`sqlite_repository.hpp/.cpp` | 上述对象的建表、增删改查、事务替换映射 |
| 学生画像模型 | `src/modules/student_profile/model.hpp` | 学生读模型、指标值、标签、学生标签、画像快照 |
| 学生画像仓储 | `repository.hpp`、`sqlite_repository.hpp/.cpp` | 上述对象的建表、upsert、查询、快照保存 |
| 跨平台 HTTP | `src/http_server.cpp` | Windows 使用 Winsock，Linux 使用 POSIX socket，接口不变 |
| VS Code 配置 | `.vscode/`、`CMakePresets.json` | 选择 preset 后可直接构建、调试、跑测试 |
| 数据层测试 | `tests/storage_test.cpp` | JSON、两个仓储的真实 SQLite 读写测试 |

## 2. 分层结构

```
HTTP 请求
   │
   ▼
module.cpp / service.cpp        参数校验、用例编排、权限与数据范围
   │
   ▼
repository.hpp                  模块的持久化接口（可替换实现、方便测试）
   │
   ▼
sqlite_repository.cpp           SQL 与表结构
   │
   ▼
platform::Database              SQLite 连接、参数绑定、事务
```

约定：

- `module.cpp` 只做模块注册和路由登记，不放业务逻辑。
- `service.cpp` 放用例级逻辑，例如导入校验、失败重试、画像计算、权限范围判断。
- `repository` 只负责读写，不判断“能不能导入”“该不该预警”。
- HTTP 请求/响应结构仍然使用 `platform::Request` / `platform::Response`，不新增第二套 Web 框架。

## 3. 数据采集与接入模块（M1）

### 3.1 用例与计划接口

路由前缀：`/api/modules/data-ingestion`。下表是**规划**，当前尚未注册。

| 用例 | 方法与路径（相对前缀） | 数据层支撑 |
| --- | --- | --- |
| UC-DC-01 登记数据源 | `POST /sources` | `create_data_source` |
| UC-DC-02 配置导入任务 | `POST /tasks` | `create_import_task` |
| UC-DC-03 执行导入任务 | `POST /tasks/:task_id/run` | `start_import_run`、`add_raw_record`、`finish_import_run` |
| UC-DC-04 查看导入结果 | `GET /runs/:run_id`、`GET /runs/:run_id/records?failed=1` | `find_import_run`、`list_raw_records` |
| UC-DC-05 接收外部数据推送 | `POST /push` | 复用 `start_import_run` / `add_raw_record` |
| UC-DC-06 调度采集任务 | `PUT /tasks/:task_id/schedule` | `update_import_task_status`，调度器后续实现 |
| UC-DC-07 维护字段映射规则 | `PUT /sources/:source_id/mappings` | `replace_field_mappings` |

辅助查询可直接复用：`GET /sources`、`GET /sources/:id`、`GET /tasks`、`GET /tasks/:id`。

### 3.2 表结构

表名统一加 `ing_` 前缀，避免与其它模块冲突。

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `ing_data_source` | `name`、`kind`、`access_mode`、`owner` | 数据源登记 |
| `ing_field_mapping` | `data_source_id`、`source_field`、`standard_field`、`transform_expr` | 源字段到标准字段的映射 |
| `ing_import_task` | `data_source_id`、`import_mode`、`schedule_expr`、`validation_rules`、`status` | 任务配置，`validation_rules` 存 JSON |
| `ing_import_run` | `task_id`、`status`、`total_count`、`success_count`、`failure_count` | 每次执行的结果 |
| `ing_raw_record` | `run_id`、`source_row_no`、`payload`、`valid`、`error_reason` | 原始记录与失败原因 |

已经考虑的约束：

- `ing_raw_record` 对 `(run_id, source_row_no)` 唯一，重试时同一行不会重复入库。
- 外键开启（`PRAGMA foreign_keys = ON`），删除数据源会级联删除映射。
- `replace_field_mappings` 在一个事务里删除旧映射再写新映射，避免只改了一半。

## 4. 学生画像模块（M3）

### 4.1 用例与计划接口

路由前缀：`/api/modules/student-profile`。下表是**规划**，当前尚未注册。

| 用例 | 方法与路径（相对前缀） | 数据层支撑 |
| --- | --- | --- |
| UC-SP-01 维护标签体系 | `POST /tags`、`GET /tags` | `upsert_tag`、`list_tags` |
| UC-SP-02 计算画像指标 | `POST /recalculate` | `upsert_metric`、`replace_student_tags`、`save_snapshot` |
| UC-SP-03 查看个人画像 | `GET /students/:student_id` | `find_student`、`list_metrics`、`list_student_tags`、`find_snapshot` |
| UC-SP-04 查看标签依据 | `GET /students/:student_id/tags/:tag_code/evidence` | `list_student_tags` + `find_tag` |
| UC-SP-05 对比画像 | `GET /students/:student_id/compare?peer=...` | 读取双方指标与快照 |
| UC-SP-06 导出画像报告 | `GET /students/:student_id/report` | 读取快照；PDF 生成留到前端/后续实现 |
| UC-SP-07 查看学生画像详情 | `GET /students?class=...&major=...` | `list_students` + 指标查询 |

数据范围（学生本人 / 班级 / 学院 / 全校）和脱敏属于 M6“数据服务与权限管理”的职责，画像模块先预留“数据范围过滤”的入口，后续接入 M6 的鉴权结果。

### 4.2 表结构

表名统一加 `sp_` 前缀。

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `sp_student` | `student_id`、`name`、`major`、`class_name`、`grade` | 学生读模型，主数据由治理模块负责 |
| `sp_metric_value` | `student_id`、`metric_code`、`term`、`value`、`source` | 指标值，按学生+指标+学期唯一 |
| `sp_tag` | `code`、`name`、`dimension`、`description` | 标签定义 |
| `sp_student_tag` | `student_id`、`tag_code`、`evidence` | 标签结果，`evidence` 存计算依据 JSON |
| `sp_profile_snapshot` | `student_id`、`term`、`payload` | 某周期的画像快照 |

`sp_student` 是读模型：治理模块合并出学生主数据后同步过来，画像模块不负责“一人多号”的归并。

## 5. 数据库使用方式

- 默认数据库文件：`data/platform.db`。
- 可用环境变量覆盖：

  ```powershell
  $env:PLATFORM_DB_PATH = "D:\tmp\platform.db"
  ```

- 每个模块在构造仓储时执行 `CREATE TABLE IF NOT EXISTS`，所以第一次启动会自动建表。
- 连接参数已经开启外键、WAL 和 5 秒 busy timeout。
- 表名按模块加前缀是硬约定：合并后五个模块共用一个数据库文件，但不会互相撞表。
- 当前没有做“版本化迁移”。新增列时，先和组内约定，再在各自仓储里写兼容逻辑；不要直接删表。

## 6. 构建与运行

### 6.1 VS Code（Windows）

1. 安装并启用 CMake Tools、C/C++ 扩展（当前机器已经安装）。
2. 打开项目根目录，选择 preset `windows-vs2026`。
3. `F7` 构建，`F5` 运行 `platform_server`（`.vscode/launch.json` 已配置）。
4. CMake Tools 的 Testing 面板或 `ctest --preset windows-vs2026` 跑测试。

命令行等价操作：

```powershell
cmake --preset windows-vs2026
cmake --build --preset windows-vs2026
ctest --preset windows-vs2026
.\build\windows-vs2026\Debug\platform_server.exe 8080
```

如果 `ctest` 列表里没有 `http_smoke`，说明 CMake 没找到可用的 Python。可以显式指定：

```powershell
cmake --preset windows-vs2026 -DPython3_EXECUTABLE="C:/Users/你的用户名/AppData/Local/Programs/Python/Python314/python.exe"
```

### 6.2 Linux

```bash
cmake --preset linux-debug
cmake --build --preset linux-debug
ctest --preset linux-debug
./build/linux-debug/platform_server 8080
```

浏览器打开 <http://127.0.0.1:8080/>。

## 7. 下一步实现顺序

建议按“先一条竖切，再铺开”的顺序做，避免六个接口同时半成品：

1. **数据源登记与查询**（UC-DC-01）：在 `module.cpp` 里创建 `Database`、`SqliteIngestionRepository`，注册 `POST /sources`、`GET /sources`；补充 `app_test` 或新测试。
2. **字段映射与导入任务配置**（UC-DC-02、07）：实现 `PUT /sources/:id/mappings`、`POST /tasks`。
3. **导入执行与结果查看**（UC-DC-03、04）：解析请求体中的记录数组，逐行校验，写 `ing_raw_record`，汇总 `ing_import_run`。
4. **标签维护与画像计算**（UC-SP-01、02）：先做标签 CRUD，再实现“指标 → 标签 → 快照”的计算。
5. **画像查询与标签依据**（UC-SP-03、04、07）：查询接口先返回 JSON，权限范围与脱敏后续接入 M6。
6. **对比与报告**（UC-SP-05、06）：报告可以先生成 HTML/JSON，PDF 留到最后与前端一起做。
7. **外部推送与调度**（UC-DC-05、06）：推送复用导入执行；调度需要后台线程/定时器，放在基础链路稳定之后。

每个接口实现时同步补测试：数据层测试放 `tests/storage_test.cpp`，应用层测试放 `tests/app_test.cpp`，跨进程验证放 `tests/http_smoke.py`。

## 8. 合并注意事项

- 当前 `feature/WeiEnRui` 是从较早的 `main` 分出来的，本身不包含后来加入的 C++ 骨架。提交本次框架后，先把 `main` 合进本分支再继续开发，避免最后合回主分支时共享文件出现 add/add 冲突：

  ```powershell
  git add -A
  git commit -m "搭建数据采集与学生画像模块框架"
  git merge origin/main -X ours
  ```

  `-X ours` 表示冲突时保留本分支版本；本分支的骨架已经包含 `main` 的内容并做了扩展，所以这样是安全的。
- 新增 `.cpp` 文件要加入 `CMakeLists.txt` 的 `platform_core`；这是五个人最容易冲突的地方，提交前先同步主分支。
- 共享文件 `include/platform/app.hpp`、`src/app.cpp` 尽量不改；确实要改先在群里约定。
- 现有 `tests/app_test.cpp` 和 `tests/http_smoke.py` 断言所有模块路由为空。第一次注册业务路由时，这两处会失败，需要同步改成“路由存在且行为正确”。
- 表名坚持 `ing_` / `sp_` 前缀；跨模块读取（例如画像读治理模块的学生主数据）通过 service 接口或只读查询，不要让一个模块直接改另一个模块的表。
- 数据库文件不提交（`.gitignore` 已忽略 `data/*.db*`），仓库里只保留表结构和样例数据脚本。
